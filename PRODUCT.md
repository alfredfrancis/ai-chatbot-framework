# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Two audiences, weighted equally:

- **People on small teams who don't write code**: founders, operations, sales, admin. Someone technical
  deploys the server once; colleagues each get an account and use the agent for real work: reading their
  files, drafting, researching, running recurring jobs.
- **Individuals and households**: one person self-hosts it as a private assistant, for themselves and
  maybe their family.

In both cases the person in the chat is not a developer, and the person who installed it may not be
around to help. Desktop is the main workplace; phones (installed as a PWA) are for checking in and quick
asks.

## Product Purpose

A self-hosted AI agent that does work, not just answers. Each user types what they need; the agent reads
their files, runs code on its own private computer, uses their connected apps, remembers how they like
things, and keeps working on a schedule. Success: a non-technical person gets a real result (a file, a
sent summary, an updated tracker) without learning any tool first, and comes back the next day because
the agent remembered.

## Positioning

An agent built for non-developers. Most agent tools assume a developer at the keyboard; this one is set
for comfort over density (16px text, 40px controls), uses plain words, needs no per-user setup, and shows
its work as readable steps instead of logs. Self-hosting, a private sandbox per person and open formats
make that trustworthy, but ease is the lead.

## Operating Context

- One chat per job, with the agent's steps (ran, wrote, edited, used) visible as it works; the user can
  type while it works (steering) or stop it.
- Supporting areas: Files (the user's `/workspace`), Skills, Tasks (scheduled prompts), Connections (MCP
  apps with OAuth), Projects (shared instructions and a folder), and up to five personal apps the agent
  builds, each with its own chat beside it.
- Memory is plain files the user can read: `context.md` (about them) and `memory.md` (what the agent
  remembers).
- Also reachable from editors and other apps over the Agent Client Protocol.

## Capabilities and Constraints

- Any LangChain chat model; Claude by default; users may bring their own key.
- One Docker sandbox per user; everything the agent runs goes through it.
- The agent has four tools (`read`, `write`, `edit`, `bash`) plus sub-agents; MCP and skills are the
  extension points, not new built-in tools.
- Personal apps and views in chat are OpenUI Lang rendered with the product's own component library; the
  agent never writes HTML.
- Scales out: stateless app processes behind Caddy with PostgreSQL and Redis.
- Terminology users see: chats, files, skills, tasks, connections, projects, apps. Not "workspace",
  "MCP", "sandbox" or "tokens" in primary UI copy.

## Product Principles

1. **Results over conversation.** The agent acts and checks its work; a finished file beats a description
   of one.
2. **Show the work, plainly.** Every step is visible in words a non-developer understands; nothing hides
   behind a spinner.
3. **Plain files, owned by the user.** Memory, skills and apps are files they can open, and the server
   is theirs.
4. **Comfort beats density.** Larger type and targets, one primary action per screen, everything also
   reachable by keyboard.
5. **Lean by design.** A new capability is a skill, an MCP connection or a file before it is a new tool or
   a new screen.

## Accessibility & Inclusion

WCAG 2.2 AA: text contrast ≥ 4.5:1 and UI contrast ≥ 3:1 in both themes, full keyboard use with visible
focus, targets ≥ 40px, labelled controls (tests select by role and label), `prefers-reduced-motion`
respected, and layouts that work from 390px wide up.
